# LIFE-CORE-014 — Cross-UID Service Authorization & Transactional Recovery Hardening

Opt-in `AuthorizedLifecycleService` uses Linux `SO_PEERCRED` to authorize a set of explicit client UIDs. Socket directory is service-owned `0711`, socket is `0666` so distinct UIDs can connect, and authorization occurs before processing the request. Database is in a **separate** service-owned `0700` directory; database, WAL and SHM must be owner-owned `0600`. Service UID is excluded from the client allowlist. Only health and snapshot are implemented; production transitions are denied.

This deliberately does not alter the legacy owner-only `LifecycleService` or its supervisor. The opt-in service is not supervised by LIFE-CORE-013. Its socket may be replaced by a privileged attacker; client-side server authentication is not implemented. World-connectable socket may permit denial of service; use network namespace, quotas, service manager and MAC policy for production designs. Service process must be provisioned under a dedicated unprivileged UID by OS administrator; the implementation does not create users or drop privileges. UID 0 tests exercise different credentials but are not proof of security against root.

Transactional fault injection uses independent child processes killed with SIGKILL immediately before or after SQLite COMMIT. SQLite rollback and committed-state persistence are verified. These are process-crash tests, not power-loss or fsync durability tests. No direct legacy API can bypass kernel DAC from an unauthorized UID when the private directory is enforced; same-UID or root processes remain able to bypass. No hardware or real-life support equipment is controlled.
