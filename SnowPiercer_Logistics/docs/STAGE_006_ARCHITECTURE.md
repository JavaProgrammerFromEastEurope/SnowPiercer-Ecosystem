# Stage 006 architecture
The new optional `recover_after_witness_cas` function is an offline, single-writer recovery entrypoint. It holds the service flock, consumes a local permit marker durably before reading recovery artifacts, compares the witness state against verified SQLite event head and the phase journal, then atomically replaces the checkpoint and removes the phase journal. Crash after consuming a permit requires an independently issued fresh permit. This is NOT a complete production broker. Legacy APIs remain accessible, and there is no cross-UID deployment configuration. The service's existing online recovery path remains unchanged.
