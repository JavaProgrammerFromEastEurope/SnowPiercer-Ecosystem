# TrainOS v103 — preserved failed / interrupted verification attempts

The following runs are intentionally retained. They MUST NOT be counted as completed passing regressions.

- `combined_baseline.*`: uncorrected broad regression using a malformed `PYTHONWARNINGS` entry for `pytest.PytestUnraisableExceptionWarning`, plus missing pytest.ini in temporary nested pytest executions. It completed with failure. Subsequent test runs pass the pytest-specific warning via pytest CLI, and retain the two standard Python warnings as errors in `PYTHONWARNINGS`.
- `combined_1.*`, `combined_2.*`: strict broad regressions that still passed inherited warnings to nested pytest without project configuration. The temporary-path tests generated pytest-asyncio's configuration deprecation (not a TrainOS regression), causing six failures. A separately captured `nested_config_probe.*` passed seven affected tests with explicit `PYTEST_ADDOPTS=-c PROJECT/pytest.ini`. Later complete combined runs use the same explicit configuration; no warning filters were disabled.
- `combined_3.*`: two early verification launchers temporarily used the same evidence prefix while the first process was still exiting. Its stdout may have been overwritten/interleaved; this run is **not** relied upon for acceptance, even though its final JSON status reports PASS. Unique, non-overlapping final combined iterations `combined_6`–`combined_8` are the acceptance set. The complete overwritten intermediate attempt cannot be reconstructed; this provenance limitation is disclosed rather than hidden.
- `runner_focused_1.*`: the first newly added residual-group test checked its child before asynchronous SIGKILL delivery had fully taken effect. The test was updated to poll a bounded interval for the non-running or zombie state; the repeat passed.
- `strict_full_2.*`: 1,494 passed and one test failed because `scripts/ci/run_stage_matrix.sh` lost its executable bit during local Python `zipfile.extractall`. The v101/v102 ZIP metadata confirms mode 0755. All three previous executable shell artifacts were restored to 0755; `exec_bit_recheck.*` passed. The archive builder verifies these permissions.
- `kernel_default_1.*`, `kernel_default_2.*`: manually interrupted strictly serial default Kernel Runner attempts, recorded as exit 143 and **not completed**. Runtime throughput on this container was materially slower than archived Codex v101 environment. They are not treated as test failures inside the unexecuted files, nor as evidence of a full default completion.
- `runner_sigkill_boundary.json`: deliberately negative test. SIGKILL of the Runner bypasses its own Python cleanup and leaves a child alive; a separate local Linux subreaper probe then kills/reaps that child. This is a real safety deficiency and reason for NO-GO.
- `warning_enforcement_probe.json`: intentionally raises both warning classes; the two synthetic pytest test failures are **expected**, proving the warning policy is enforced.

All successful and unsuccessful verification attempts are distinguishable by status, exit code, stdout, stderr and bound in `VERIFICATION_SUMMARY.json` when the archive is finalized.
