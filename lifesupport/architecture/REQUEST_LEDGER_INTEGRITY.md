# LIFE-CORE-018 — Request Ledger Integrity & Recovery Admission

Opt-in `LedgerAdmission` verifies existing HardenedLifecycle journal and every receipt's event mapping, then compares the complete canonical receipt snapshot to a separately stored HMAC-SHA256 anchor. Every accepted write updates the anchor after the SQLite COMMIT. A crash in this gap causes a fail-closed mismatch; an operator must review independent evidence before calling `reconcile` with an explicitly approved snapshot. The implementation does not claim atomicity across SQLite and filesystem.

Trust boundary: anchor key and anchor file must be protected from the SQLite administrator and service compromise; this prototype does not provide HSM or a monotonic hardware counter. A privileged attacker controlling both anchor and key can forge history. A database and anchor jointly rolled back are not detected. Read/write production IPC from earlier stages is NOT automatically forced through LedgerAdmission; enabling it requires explicit service wiring. `reconcile` checks count and maximum sequence monotonicity but cannot prove a prefix chain from one digest; human approval must be backed by independent evidence.
